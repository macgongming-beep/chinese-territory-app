# 전출자의 정기방문 기록을 보존하고 재배정한다

- 상태: **승인, 운영 미적용**
- 결정일: 2026-09-06
- 관련 기능: 정기방문 관리, 사용자 삭제, 담당자 재배정

## 배경

계정을 삭제하면 `purge_user_name_references`가 앞으로의 배정을 정리한다.
세대 담당 행인 `regular_visits`는 제거하고, 활동·방문 이력이 담긴 `return_visits`는
삭제하지 않은 채 `assigned_user_name`만 비운다.

운영에서 실제로 다음 세 항목이 이 상태로 발견됐다.

| return_visits.id | 장소 | 남은 기록 이름 |
| --- | --- | --- |
| 19 | 김량장동 26 1층 첫집 | 김무혁 |
| 20 | 영통동 10 201호 | 김무혁 |
| 27 | 김량장동 26 2층 | 김지혜 |

김무혁·김지혜는 현재 `app_users`에 없다. 전출했거나 계정이 삭제된 것으로 보이며,
누가 이어받을지는 자료만으로 자동 결정할 수 없다.

## 결정

1. **계정이 없어져도 `return_visits`와 `return_visit_logs`는 보존한다.**
2. 기존 담당자를 임의의 현재 사용자로 자동 교체하지 않는다.
3. 관리자·개발자 화면에서 해당 항목을 `담당자 재지정 필요`로 표시한다.
4. 화면에는 남아 있는 기존 기록 이름(`assigned_user_name`, 없으면 `created_by`)과
   최근 결과(`만남`/`부재`)를 보여준다.
5. 관리자가 승인된 활성 사용자를 선택하면 `return_visits.assigned_user_name`과
   연결 세대의 `regular_visits.visitor_name`을 **한 트랜잭션에서 함께** 맞춘다.
6. 재배정해도 `created_by`와 과거 `return_visit_logs`는 바꾸거나 지우지 않는다.

## 이유

- 정기방문은 단순한 담당 목록이 아니라 **반응이 있었던 장소와 관계의 이력**이다.
- 전출은 과거 방문이 없었던 일이 되었다는 뜻이 아니다.
- 좋은 반응을 보인 사람을 잃으면 다음 봉사자가 중요한 장소를 놓칠 수 있다.
- 자동 재배정은 새 담당자의 동의와 지역·언어·상황을 알지 못한 채 책임을 떠넘긴다.
- 기존 이름을 보존하면 관리자가 사정을 아는 사람에게 물어보고 제대로 이어줄 수 있다.

## 지켜야 할 계약

- 사용자 삭제 시 과거 방문 로그를 삭제하지 않는다.
- 담당자가 비었거나 현재 승인된 활성 사용자 명단에 없으면 끊긴 담당으로 본다.
- 승인 대기·차단·비활성 사용자는 재배정 후보가 아니다.
- 일반 사용자는 재배정 RPC를 호출할 수 없다.
- 재배정은 두 표 중 하나만 바뀌는 반쪽 상태를 만들지 않는다.
- 저장 실패 시 담당자 선택창을 닫지 않는다.
- 연결되지 않은 `return_visits`는 `regular_visits`를 새로 만들지 않는다.
- 기존 등록자와 방문 로그는 감사·인수인계 정보이므로 재배정 과정에서 보존한다.

## 포기한 대안

### 계정 삭제와 함께 정기방문 전체 삭제

방문 로그가 `return_visits`에 `ON DELETE CASCADE`로 연결돼 있어 과거 반응까지
사라진다. 데이터 정리처럼 보이지만 봉사 인수인계 정보를 잃으므로 사용하지 않는다.

### 관리자나 임의 사용자에게 자동 재배정

실제 후임자를 시스템이 알 수 없고 잘못된 책임 배정이 조용히 남으므로 사용하지 않는다.

### 이름만 새 값으로 직접 UPDATE

`return_visits`와 `regular_visits`가 서로 다른 담당자를 가질 수 있어 화면마다 담당자가
다르게 보인다. 반드시 서버 트랜잭션 RPC를 사용한다.

## 결과와 비용

- 관리자는 전출자의 장소를 직접 검토하고 새 담당자를 지정해야 한다.
- 재지정 전까지 해당 항목은 목록에 경고로 남는다.
- 이름은 외래키가 아닌 과거 기록 문자열이므로, 현재 계정이 없어도 표시할 수 있다.
- 삭제가 꼭 필요하다면 방문 로그 보존·익명화 계약을 별도 결정으로 먼저 정해야 한다.
