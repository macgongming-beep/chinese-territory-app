# 정기방문 종료와 장소 수정 요청을 분리한다

날짜: 2026-09-06

## 결정

- 정기방문을 그만두는 것은 건물·세대·방문 기록 삭제가 아니다.
- `return_visits`는 삭제하지 않고 종료 시각·종료자·종료 사유를 남긴다.
- 현재 담당 표인 `regular_visits`만 해제한다. 다른 담당자로 이미 바뀐 행은 지우지 않는다.
- 종료된 세대를 다시 정기방문으로 등록하면 과거 `return_visit_logs`를 살린 채 재활성화한다.
- 건물이나 세대가 없어졌거나 자료가 틀렸다는 보고는 별도의 `place_change_requests`에 남긴다.
- 관리자·개발자는 설정의 `자료 수정 요청`에서 확인하고, 실제 수정·병합·삭제를 마친 뒤 완료 처리한다.

## 이유

담당자가 전출하거나 계정이 삭제돼도 그 사람이 남긴 방문 결과는 다음 담당자가 판단할 근거다.
담당 종료와 장소 삭제를 한 버튼에 묶으면, “내가 더는 방문하지 않는다”는 흔한 상황에서
정상 건물과 과거 기록까지 잃을 수 있다. 반대로 실제 철거·중복·오기입은 관리자가 확인해야
하므로, 사용자가 직접 자료를 지우는 것보다 문맥이 담긴 요청으로 넘기는 편이 안전하다.

## 불변 계약

1. 종료해도 `buildings`, `units`, `return_visit_logs`는 보존한다.
2. 종료자가 아닌 새 담당자의 `regular_visits` 행을 지우지 않는다.
3. 장소 문제 요청에는 대상이 나중에 삭제돼도 알아볼 수 있도록 이름·주소·호수 스냅샷을 남긴다.
4. 요청을 완료로 표시하는 행위 자체는 자료를 삭제하지 않는다. 관리자가 실제 조치를 먼저 한다.
5. 계정 삭제 정리 과정에서도 방문 기록은 지우지 않는다. 담당자 재지정 대상으로 남긴다.

## UI 위치

- 사용자는 정기방문 상세와 목록에서 `정기방문 종료`를 누른다.
- 종료 사유와 장소 문제는 서로 다른 입력이다. 장소 문제는 선택 사항이다.
- 관리자 요청함은 반복적으로 확인하는 관리 기능이므로 `설정 → 자료 수정 요청`에 둔다.

## 후속 작업

건물·세대 직접 삭제 권한은 `20260906_1100_guard_place_deletion.sql`에서 좁혔다.
인도자는 새로 만든 빈 장소를 즉시 정리할 수 있지만, 방문 기록·정기방문·배정 등 연결
자료가 있으면 삭제하지 않고 `place_change_requests`로 보낸다. 일반 사용자는 항상 요청만
만들고, 관리자·개발자는 명시적인 삭제 확인 뒤 처리한다. 일괄 삭제 결과는 한 번만 알린다.
방금 잘못 등록한 장소는 상태·중국어 표시가 있어도 30분 안에는 인도자가 바로 정리할 수
있다. 30분이 지났거나 연결 자료가 생기면 관리자 요청으로 전환한다.

연결 자료가 있는 장소는 관리자·개발자도 일반 지도 화면에서 즉시 삭제하지 않는다.
삭제 요청에 세대·방문 기록·정기방문·전화 조사·식당 배정 수를 저장하고, 설정의 요청함에서
그 영향을 펼쳐 본 뒤 `영구 삭제`를 눌러야 한다. 영구 삭제와 요청 완료는 한 트랜잭션이다.
반려는 요청 상태만 바꾸고 장소와 연결 기록은 그대로 보존한다. 주소·이름·호수 수정은
삭제와 다르므로 인도자·관리자가 현장에서 계속 직접 처리한다.
