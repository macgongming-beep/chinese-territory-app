# 건물은 기본 용도, 세대는 예외 용도를 갖고 출입불가는 건물에 기록한다

- 상태: **승인, 운영 미적용**
- 결정일: 2026-09-06
- 관련 기능: 구역 필터, 지도 핀, 건물·세대 등록, 식당, 정기방문, 출입불가

## 배경

`buildings.type`만으로 주택과 상가를 구분하면 주택 건물 1층의 식당이나 상가가 상가
필터에서 사라진다. 반대로 건물 유형을 상가로 바꾸면 같은 건물의 주택 세대가 상가로
분류된다. 식당 등록 경로는 새 건물을 상가로, 정기방문 등록 경로는 주택으로 고정해
같은 실제 건물을 서로 다르게 만들 가능성도 있었다.

과거에는 건물 전체에 들어갈 수 없다는 사실을 `출입불가`라는 가짜 세대로 표현했다.
운영의 가짜 세대 11개에는 모두 실제 방문 기록이 있으므로 세대를 바로 삭제하면
`ON DELETE CASCADE`로 확인자와 날짜까지 사라진다.

## 결정

1. `buildings.type`은 그 건물에 새로 추가되는 세대의 **기본 용도**다.
2. `units.usage_type`은 건물과 다른 예외만 저장한다. 값은 `null | 주택 | 상가`다.
3. 화면은 내부 상속 규칙을 설명하지 않고 항상 `주택 / 상가` 두 선택지만 보여준다.
4. 선택이 건물 기본과 같으면 `null`, 다르면 해당 값을 저장한다.
5. 식당 세대는 언제나 상가다. `is_restaurant=true`가 가장 우선하며 DB 트리거도
   `usage_type='상가'`를 강제한다.
6. 혼합은 별도 저장값이나 사용자 배지가 아니다. 주택·상가 세대를 모두 가진 건물에서
   계산되는 상태일 뿐이다.
7. 용도 필터, 진행률, 통계, 지도 핀은 선택한 용도의 세대만 같은 공통 함수로 계산한다.
8. `units_surveyed`는 어떤 용도 필터에서도 무시하지 않는다. 등록된 세대를 모두
   방문했어도 실제 세대를 다 파악하지 못했다면 완료로 보이지 않는다.
9. 건물 전체의 출입불가는 `buildings.access_status`에 저장하고 확인자·날짜·메모는
   `building_access_events`에 남긴다.
10. 기존 가짜 세대의 방문 기록은 건물 이력으로 복사해 검증한 뒤에만 원본을 정리한다.

## 이유

- 대부분의 건물은 한 용도이므로 모든 세대에 같은 값을 중복 저장할 필요가 없다.
- 예외만 저장하면 건물 기본을 바꿀 때 기본을 따르는 세대는 함께 바뀌고, 사람이 따로
  지정한 세대는 보존된다.
- 식당은 업종 자체가 상가라는 강한 사실이므로 사람이 주택으로 덮어쓰게 두지 않는다.
- 건물 단위 필터만 유지하면 혼합 건물의 일부 세대가 계속 미방문으로 남거나 상가
  봉사에서 누락된다.
- 출입불가는 호수 이름이 아니라 건물 접근 상태다. 다만 누가 언제 확인했는지는 다음
  방문 판단의 근거이므로 상태 전환 과정에서 지우지 않는다.

## 지켜야 할 계약

- 실제 용도는 `isRestaurant ? 상가 : (usageType ?? building.type)`이다.
- 주택 건물 안 식당도 상가 필터에 나타난다.
- 혼합 건물의 상가/주택/전체 진행률은 각각 해당 세대만 집계한다.
- 건물 기본 유형 변경은 관리자·개발자·인도자만 서버에서 허용한다.
- 일반 사용자의 세대 추가는 허용하고, 새 세대 용도는 건물 기본값으로 시작한다.
- 일괄 추가도 단일 추가와 같은 용도를 모든 새 세대에 적용한다.
- 식당 등록은 기존 주택 건물을 재사용할 수 있고 건물 기본 유형은 바꾸지 않는다.
- 식당과 정기방문 등록은 같은 주소 키와 같은 advisory lock을 사용한다.
- 출입불가 건물의 과거 방문 기록은 원본 제거 전에 건물 이력과 대조한다.
- `스톤빌 B05`처럼 같은 건물·호수 중복에 양쪽 기록이 있으면 자동 병합하지 않는다.

## 포기한 대안

### 건물만 주택·상가로 구분

단순하지만 주상복합의 필터·진행률이 실제 봉사 대상과 맞지 않는다.

### 모든 세대에 용도를 저장

건물 기본값과 중복되고, 건물 유형을 바꿀 때 어떤 값이 사람의 의도인지 알 수 없다.

### 사용자에게 `혼합`을 선택하게 함

혼합은 건물 안 세대 구성에서 자동으로 알 수 있으며 사용자가 의미를 이해하고 별도로
관리할 이유가 없다.

### 출입불가 가짜 세대를 즉시 삭제

연결된 방문 기록 11건이 함께 삭제되므로 사용하지 않는다.
