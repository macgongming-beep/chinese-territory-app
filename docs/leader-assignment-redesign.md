# 인도자 배정 재설계 — 일정상세 통합 + 지도 기반 구역 배분 (리뷰 요청)

> **목적**: 코덱스(및 다른 리뷰어) 검토용 설계 문서.
> 인도자 배정 기능을 별도 탭에서 → 일정상세(이벤트 디테일)로 통합하고,
> 구역 배분에 "지도 색칠" 방식을 새로 도입하는 구상.
> 작성일: 2026-05-30

---

## 0. 한 줄 요약

> "인도자 배정을 별도 탭에서 빼서 일정상세 안으로 넣는다. 배정은 (1) 팀 짓기 → (2) 구역 배분 두 화면으로 가르고, 구역 배분은 지도에서 폴리곤을 팀 색으로 칠하는 방식 + 목록 토글을 제공한다. 마지막에 일정상세에서 '배정 공유' 한 번."

## 1. 배경 / 현재 구조

### 1.1 현재 인도자 배정 (`MobileLeaderAssignment.tsx`, 1292줄)
- **별도 하단 탭 "배정"**에서 진입
- 진입하면 오늘 일정 목록에서 일정 하나 또 고름 (캘린더에서 이미 봤는데 중복)
- 3-step 위저드:
  1. **카드 선택** — 담당 카드(~43개)를 그룹별로, 검색/미배정 토글, 탭하면 팀에 추가
  2. **팀 구성** — 팀(=카드 묶음 + 사람 묶음) 다듬기, 팀 추가/삭제, 멤버 칩 추가/제거, "카드 변경" 누르면 step1로 점프
  3. **참가자** — 참가자별 소속 팀 표시, 미배정 경고, 배정 공유/임시저장
- 데이터 모델:
  - `team = { id, name, color, cardIds[], members[] }`
  - draft를 `localStorage` (`mobileLeaderAssignmentDraft:{eventId}:{user}`)에 저장
  - 공유 상태: `draft / confirmed / shared`
  - 모든 배정 콜백이 이미 `eventId` 스코프: `onAssignCardsToEventParticipantsBulk(eventId, ...)`

### 1.2 핵심 관찰
- **배정은 이미 "일정 단위"** → 일정상세는 이미 eventId를 알고 있으니, "일정 또 고르기" 단계가 군더더기
- **Step1(카드선택)·Step2(팀구성)은 같은 작업의 양면**이고 Step3(참가자)도 Step2와 겹침 → step 전환이 잦아 맥락이 끊김
- 담당 카드 43개를 좁은 step1에 욱여넣음 → 답답

### 1.3 일정상세 (`admin/AdminEventDetailSheet.tsx`, 697줄)
- 바텀시트. Hero(시간/제목/인도자) + 신청하기 + 상세 + 위치 + 신청자 칩 strip + (shared면) 공유된 배정 표시
- 이미 신청자 전원을 칩으로 보여줌

### 1.4 지도 (`MapCanvas.tsx`)
- `cardBoundaries` (카드별 폴리곤), `onSelectCardBoundary(cardId)` (폴리곤 탭 핸들러),
  `selectedCardIds: Set` (여러 카드 색칠 강조), 폴리곤별 fillColor 지정 가능
- **즉 "탭하면 그 구역이 팀 색으로 칠해진다"가 기존 인프라로 거의 됨**

## 2. 제약 / 도메인 사실 (인도자 인터뷰 기반)

1. **한 팀에 카드 여러 개** 흔함: 구역 2개, 또는 구역+비공식 섞임 → 팀 개념 유지 필수
2. **누구랑 누구 짝**은 인도자가 직접 고민 → 사람 자동분배 불가
3. **형식은 비슷하나 인원은 매번 다름** → 팀 골격 복사는 가치 있으나 사람은 매번 교체
4. **하루에 한 구(區)만** 감 (기흥구 OR 처인구, 둘 다는 너무 멂) → 구 단위 범위 좁히기 자연스러움
5. **비공식 카드·식당은 폴리곤 없음** → 지도 배정 대상 아님. 구역과 별도로 배정
6. **경계선(폴리곤) 안 그린 구역카드는 인도자에게 배정 안 함** → 폴백 불필요
7. **관리자 카드 배정**(인도자에게 구역 소유권 배정)은 이번 범위 아님. 그대로 둠

## 3. 새 설계

### 3.1 전체 흐름
```
일정상세 (AdminEventDetailSheet)
  └ [팀 구성 & 배정 →]   ← 인도자/관리자만 노출
       ↓ 풀스크린 진입 (바텀시트 아님)
  화면1: 팀 짓기 (사람 묶기 + 비공식/식당 배정)
       ↓ 팀 카드 탭 (헤더 팀바로도 전환 가능)
  화면2: 구역 배분 (지도/목록 토글)
       · 즉시 반영, 저장 버튼 없음
       ↓ 뒤로
  일정상세
    └ [배정 공유] 한 번   ← draft→shared
```

### 3.2 화면1 — 팀 짓기
```
┌─ 傳道 13:00 배정 ─────────────────┐
│ 신청 9명                           │
│ [장웅][사용자1][사용자2][사용자3]  │ ← 탭 멀티선택
│ [사용자4][사용자5][엄민석]...      │
│  ✓ 2명 선택  [→ 새 팀으로 묶기]   │
│ ═══════════════════════════════   │
│ ┌──────────────────────────────┐ │
│ │ 팀 1   장웅·사용자1        [›]│ │ ← 탭 → 화면2 (그 팀)
│ │ 🗂 신갈동4 외 1 · 📁비공식A   │ │   구역 요약
│ ├──────────────────────────────┤ │
│ │ 팀 2   사용자2·사용자3     [›]│ │
│ │ ⚠ 구역 미배정               │ │
│ └──────────────────────────────┘ │
│ 미배정 👤 사용자4 사용자5          │ ← 탭 → 팀 선택해서 추가
│                      [공유 →]    │
└──────────────────────────────────┘
```
- 사람 멀티선택 → "묶기" → 팀 생성 (컨셉 A)
- 미배정 사람은 기존 팀 멤버 영역 탭으로 추가
- **비공식/식당 배정도 여기서** (지도 밖이므로): 팀별로 "+비공식/식당" 진입
- 각 팀 카드에 구역 요약 + 미배정 경고

### 3.3 화면2 — 구역 배분 (핵심 신규)

#### 레이아웃 (헤더에 팀 카드 가로 스크롤)
```
┌─ ‹ 구역 배분 ─────────────────────┐
│ ┌────────┐┌────────┐┌────────┐    │ ← 헤더: 팀 카드 가로 스크롤
│ │● 팀1   ││ 팀2    ││ 팀3    │ →  │   활성팀 강조(●)
│ │장웅    ││사용자2 ││사용자5 │    │   탭하면 활성 전환
│ │사용자1 ││사용자3 ││        │    │   많아지면 옆으로 드래그
│ └────────┘└────────┘└────────┘    │
│ ─────────────────────────────────│
│ 📍[기흥구][처인구]      [🗺️|☰]   │ ← 구 선택 + 뷰 토글
│ ┌──────────────────────────────┐ │
│ │   🗺️ 기흥구 자동 줌           │ │
│ │   ┌────┐                     │ │
│ │   │팀1 │ ← 색+이름 라벨       │ │ ← 폴리곤 탭 = 활성팀 색칠
│ │   └────┘   ┌────┐            │ │
│ │            │팀2 │            │ │
│ │   ░░░ 미배정 └────┘          │ │
│ └──────────────────────────────┘ │
│ 팀1: 신갈동4 · 신갈동9            │ ← 활성팀 배정 요약
└──────────────────────────────────┘
```

#### 인터랙션
- **헤더 팀 카드**: 가로 스크롤, 탭하면 활성팀 전환 (활성 = ● 강조). 나갔다 올 필요 없이 팀 간 이동
- **구 선택** ([기흥구][처인구]): 그 구로 자동 줌 + 그 구 카드만 폴리곤. 마지막 선택 기억
- **뷰 토글** ([🗺️지도 | ☰목록]): 같은 데이터 두 뷰
- **지도 색칠**: 활성팀 상태에서 폴리곤 탭 → 활성팀 색+이름으로 칠 (토글로 해제). 한 팀에 여러 폴리곤 = 멀티카드 자연 해결
- **다른 팀 구역 탭**: 바로 활성팀으로 **이동(재배정)** — 확인 팝업 없음 (잘못하면 다시 탭)
- **즉시 반영**: 저장 버튼 없음. draft에 바로 기록

#### 폴리곤 시각 상태
| 상태 | 표현 |
|---|---|
| 미배정 | 회색 + 점선, 라벨 없음 |
| 활성팀 배정 | 진한 팀색 채움 + 팀 이름(흰 글씨+그림자) |
| 다른팀 배정 | 옅은 팀색 + 작은 팀 이름 |
| 폴리곤 작아 글씨 안 들어감 | 색만, 탭 시 툴팁 |

#### 목록 뷰 (토글 시)
- 기존 step1 카드 피커 재활용: 그룹별, 검색, 미배정 토글
- 각 카드에 체크 = 활성팀 배정. 지도와 상태 공유

### 3.4 비공식/식당
- 지도 대상 아님. 화면1에서 팀별로 배정 (기존 `onAssignInformalToUser`, `onAssignRestaurantToUser` 재활용)

### 3.5 배정 공유
- 화면들에서는 draft만 갱신 (즉시 반영, 저장 버튼 없음)
- 일정상세로 돌아와 **[배정 공유]** 한 번 → `onAssignCardsToEventParticipantsBulk(eventId, ..., { status: 'shared' })`
- 공유 전까지 참가자에게 안 보임 (기존 정책 유지)

## 4. 컴포넌트 분해 (재활용 vs 신규)

| 항목 | 처리 |
|---|---|
| 팀/멤버 데이터 모델 (team, draft, 공유상태) | **그대로 재활용** (백엔드 변경 0) |
| 사람 묶기 화면(화면1) | 신규 (컨셉 A) — 기존 step2/3 로직 일부 흡수 |
| 카드 피커 (목록 뷰) | 기존 step1 **재활용** |
| 지도 색칠 (화면2 지도) | 신규 — `MapCanvas`의 폴리곤 색칠/탭 인프라 위에 "활성팀→색칠" 연결 |
| 헤더 팀 카드 가로 스크롤 | 신규 (작음) |
| 구 선택 + 자동 줌 | 신규 (작음, MapCanvas fit 기능 활용) |
| 일정상세 진입점 | `AdminEventDetailSheet`에 버튼 추가 (작음) |
| 기존 배정 탭 제거 | 인도자 한정 하단 탭 제거 + 라우트 정리 |

## 5. 작업 사이즈 (잠정)

| Phase | 작업 | 규모 |
|---|---|---|
| 1 | 화면1 팀 짓기 + 일정상세 진입점 | 중 (2일) |

**총 5~6일.** 데이터 모델·백엔드 변경 없음. 지도 인프라 재활용으로 Phase 3가 생각보다 작음.

## 6. 리뷰어에게 묻는 것 (Q1~Q10)

### 6.1 구조 / UX
- **Q1.** 인도자 배정을 별도 탭 → 일정상세 통합하는 방향이 적절한가? 탭을 유지하는 게 나은 케이스가 있나?
- **Q2.** "팀 짓기(사람)" / "구역 배분(카드)" 2화면 분리가 3-step보다 정말 나은가? 분리의 함정은?
- **Q3.** 화면2 헤더에 팀 카드 가로 스크롤(활성팀 전환 겸용) — 팀 6개+ 일 때 실사용 문제 없나?

### 6.2 지도 배분
- **Q4.** "활성팀 → 폴리곤 탭 → 색칠"이 모바일에서 직관적인가? 탭 정확도/오조작 우려는?
- **Q5.** 다른 팀 구역 탭 시 **확인 없이 즉시 이동** — 위험한가? undo가 필요한가?
- **Q6.** 폴리곤에 팀 이름 라벨 — 작은 폴리곤/줌 레벨에서 가독성 전략이 충분한가?
- **Q7.** 구(區) 선택으로 범위 좁히기 — 한 일정이 두 구에 걸치는 예외는 없나? (도메인상 거의 없다지만)

### 6.3 구현 / 리스크
- **Q8.** 지도뷰·목록뷰가 같은 draft를 공유 — 상태 동기화에서 흔한 버그 포인트는?
- **Q9.** "저장 버튼 없이 즉시 반영" + 마지막 "배정 공유" — draft 유실/충돌(여러 기기 동시 편집) 위험은? 기존 localStorage draft와 어떻게 합치나?
- **Q10.** 5~6일 추정이 현실적인가? 지도 색칠/라벨에서 예상 못한 시간 잡아먹을 곳은?

### 6.4 자유
- **Q11.** 이 설계에서 빠진 큰 리스크나 더 단순하게 갈 길이 있나?
- **Q12.** 지도+목록 둘 다 vs 하나 먼저 — 어느 쪽 추천?

## 7. 작성자 잠정 결론
- 일정상세 통합 + 2화면 분리로 진행
- 지도/목록 **둘 다** 제공 (상호 보완, 지도 인프라 재활용으로 비용 적음)
- 다른 팀 구역 탭 시 즉시 이동 (확인 팝업 없음)
- 비공식/식당은 화면1에서 별도 배정
- 관리자 카드 배정은 손대지 않음
