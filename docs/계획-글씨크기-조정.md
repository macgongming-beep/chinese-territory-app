# 글씨 크기 조정

2026-08-28. **원하는 사람만 키운다. 기본 화면은 지금과 픽셀 단위로 같다.**

## 처음에 잘못 짚었던 것

첫 안은 "핀치 확대를 허용한다(A) / 설정에 글씨 크기를 만든다(B)" 중
**B 를 고르자** 였다. 리뷰에서 반려됐고 근거가 맞았다.

- **A 를 "한 줄" 로 봤다.** `index.html` 뿐 아니라 `src/main.tsx` 가
  `gesturestart/change/end` 와 두 손가락 `touchmove` 까지 막고 있었다.
- **"15px 이하 1,247곳" 으로 A 를 탈락시켰다.** 그건 iOS 위험 측정값이 아니다.
  자동확대는 `input/select/textarea` 의 **계산된 크기**에만 걸린다.
- **A 와 B 를 경쟁안으로 뒀다.** 성격이 다르다.
- **2,507곳 일괄 변환을 권했다.** 접근성 기능 하나에 거의 모든 컴포넌트 줄이 바뀐다.
- **고정 height 864곳을 위험 지표로 썼다.** 지도·아이콘·장식이 섞여 있다.

그다음 A(핀치 허용 + 입력 16px)를 먼저 넣었다가 **되돌렸다.**
사용자가 원한 것은 "**기본은 그대로 두고** 원하는 사람만" 이었는데,
입력칸을 16px 로 올리는 것은 62명 전원의 화면을 바꾸는 일이었다.

## 실제로 한 것 — `#root` 에 `zoom`

글씨 크기를 정하는 곳이 **2,515곳이고 전부 px** 이다. 그걸 다 바꾸는 대신
`#root` 에 `zoom` 을 건다. 글씨·간격·높이가 **같이** 커져서 잘리지 않는다.

```css
html[data-font-scale='large']   { --app-zoom: 1.125; }
html[data-font-scale='x-large'] { --app-zoom: 1.25; }
html[data-font-scale='large'] #root,
html[data-font-scale='x-large'] #root { zoom: var(--app-zoom); }
```

**안 켠 사람에게는 `zoom` 속성 자체가 안 걸린다.** `zoom: 1` 도 stacking context 를
만들 수 있어서, "기본은 아무것도 안 바뀐다" 를 보장하려면 아예 안 거는 편이 맞다.

## 브라우저에서 재서 정했다 (추측하지 않았다)

| 잰 것 | 결과 |

| 하단탭·버튼이 실제로 커지나 | 61→76, 48→60 (정확히 ×1.25) |
| 고정 요소가 어긋나나 | 안 어긋난다 (left 0 · right 375 · bottom 812 유지) |
| 가로 스크롤이 생기나 | 안 생긴다 |
| **`100svh` 는?** | ⚠ **812 → 1015 로 넘쳤다** |
| zoom 을 html/body 에 걸면? | 마찬가지로 넘치고 **가로 스크롤까지** 생긴다 |
| 보정 뒤 | 세 단계 모두 정확히 812px |

⚠ **이게 이 방식의 유일한 진짜 함정이다.** 그대로 뒀으면 지도 화면이 25% 넘쳤다.
→ `vh/svh/dvh` **43곳**을 `calc(… / var(--app-zoom, 1))` 로 나눴다.
`calc(100vh - 60px)` 같은 곳은 **화면 부분만** 나눈다 — 그 60px 은 하단탭 같은
실제 요소라 zoom 과 함께 커지는 게 맞다.

## 리뷰에서 잡힌 것 (2차)

1. **포털이 확대 밖으로 샜다.** `AppHeader` 의 알림·채팅과
   `DesktopLeaderAssignment` 의 확인창이 `document.body` 로 포털돼 있었다.
   zoom 은 `#root` 에 걸리므로 **큰 글씨로 설정한 분에게 그것만 작게** 보였다.
   → `src/lib/overlayRoot.ts` 로 `#root` 안에 자리를 만들고 둘 다 그리로 옮겼다.
   브라우저 확인: 17px → 21px 로 함께 커진다.
2. **모바일에서 켜면 PC 에서 못 껐다.** 확대는 화면 폭과 무관하게 걸리는데
   설정이 `MobileHome` 에만 있었다. 태블릿을 돌려 980px 을 넘기면 갇힌다.
   → `FontScalePicker` 를 공용으로 빼서 PC 설정 "내 정보" 에도 넣었다.
3. **첫 화면이 튀었다.** 보통 `useEffect` 라 앞사람 크기로 한 번 그려졌다.
   → `useLayoutEffect`.

## 시험

로직 7 + 감시 5. **변형으로 물리는 것을 확인했다** — 이게 본론이다:

```
vh 보정 빼기 · zoom 값 고정 · 기본에도 zoom 걸기 ·
기본일 때 표시 안 지우기 · 이상한 저장값 걸러내기 제거 · 포털을 body 로 되돌리기
```

⚠ 그중 **둘은 처음에 안 물었다:**
- '기본에도 zoom 걸기' — 시험이 "규칙 안에 `data-font-scale` 이 있나" 만 봐서
  `#root, html[data-font-scale='x-large'] #root` 처럼 **선택자 목록에 하나만**
  있어도 통과했다. 그게 정확히 위험한 경우다. → 선택자를 쪼개 하나씩 본다.
- '포털을 body 로' — `createPortal(…, document.body)` 순서만 봐서
  `const target = document.body` 로 우회됐다. → 포털을 쓰는 파일에서
  `document.body` 를 아예 못 쓰게 했다.

두 번 다 **주석까지 검사에 걸리는 문제**가 딸려 왔다 (주석의 `zoom: 1`,
"document.body 가 아니라…"). 검사 전에 주석을 걷어낸다.
