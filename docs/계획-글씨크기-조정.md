# 글씨 크기 조정

2026-08-28. **리뷰 반영본.** 처음 안(B만)은 반려됐고 그 근거가 맞았다.

## 내가 틀렸던 것

- **A(핀치 허용)를 "한 줄" 로 봤다.** 아니다. `index.html` 뿐 아니라
  `src/main.tsx` 가 `gesturestart/change/end` 와 두 손가락 `touchmove` 까지
  전역에서 막고 있었다. viewport 만 고치면 여전히 안 됐을 것이다.
- **"15px 이하 1,247곳" 으로 A 를 탈락시켰다.** 그건 iOS 위험 측정값이 아니다.
  자동확대는 `input/select/textarea` 의 **계산된 크기**에만 걸린다.
  다시 재니 **입력칸을 겨냥한 규칙 79개가 12~15px, 95개는 body(15px) 상속** —
  결론(보정이 필요하다)은 같지만 근거는 달랐다. 작은 설명문·배지까지 센 숫자로
  방법을 탈락시키면 안 됐다.
- **A 와 B 를 경쟁안으로 뒀다.** A 는 접근성 기본값이라 되돌릴 것이고,
  B 는 그 위에 얹는 선택 기능이다. 고르는 문제가 아니었다.
- **2,507곳 일괄 `calc()` 변환을 권했다.** 접근성 기능 하나에 거의 모든 컴포넌트
  줄이 바뀐다 — blame·충돌·리뷰 비용이 크다. 게다가 `index.css` 에 이미
  `--text-xs … --text-4xl` **토큰 9개**가 있는데 **19곳에서만** 쓰이고 있었다.
  그걸 살리는 편이 낫다.
- **고정 height 864곳을 위험 지표로 썼다.** 지도·아이콘·스위치·장식이 섞여 있다.
  미리 다 고치면 불필요한 레이아웃 변경이 폭발한다.

## 1단계 — 핀치 확대 복구 ✅ (했다)

```
index.html   maximum-scale=1.0, user-scalable=no  제거
src/main.tsx 전역 gesture/touchmove 차단 제거
src/App.css  @media (max-width: 979px) 에서 입력칸 16px 보장
```

`!important` 를 썼다 — 79개 규칙과 인라인 5곳을 덮어야 하는데, 같은 목적의
예외는 한 곳에 모으는 편이 각 규칙을 찾아다니는 것보다 안전하다.
체크박스·라디오·range 는 제외했다 (글씨가 없고 크기만 흔들린다).

**되돌리기 감시 시험** `src/a11yZoom.test.ts` 6개. 한 줄이면 다시 막히는
종류라 못을 박았다. 변형 4가지(확대 재차단·maximum-scale·gesture 복원·16px 제거)
전부 문다.

⚠ **실기기에서 볼 것** (여기서 확인할 수 없다):
- 지도에서 핀치가 지도 확대로 가는가, 브라우저 확대로 가는가.
  **문제가 있어도 전역으로 다시 막지 말 것** — 지도 컨테이너 범위에서 푼다
- 입력 글씨가 16px 로 커지면서 높이 고정된 입력줄(채팅 입력칸 등)이 넘치지 않는가

## 2단계 — 사용자별 글씨 크기 (아직 안 함)

**루트 한 곳에서 배율을 정한다.** 선언마다 `calc()` 를 반복하지 않는다.

```css
html { font-size: 100% }
html[data-font-size='large']   { font-size: 112.5% }
html[data-font-size='x-large'] { font-size: 125% }
```

배율은 **1 / 1.125 / 1.25**. (1.3 은 촘촘한 표·탭에서 변화가 크다)

**소비처는 점진적으로.** 이미 있는 `--text-*` 토큰을 rem 으로 바꿔 두면
그 토큰을 쓰는 곳은 저절로 따라온다. 그다음 대상 화면의 `14px` 을
`var(--text-base)` 로 옮긴다. 전면 변환이 아니다.

**먼저 적용할 화면** (많이 읽는 곳부터):
```
모바일 홈 · 지도 카드/핀 상세 · 방문 기록 · 캘린더 · 모달과 하단탭 · 설정
```

저장은 사용자별 (`chsFontScale:<userId>` — 언어와 같은 방식).
기기마다 다른 게 오히려 맞다 (폰은 크게, PC 는 보통).

## 시험 (jsdom 으로 px 을 재려 하지 않는다)

`calc`·`rem` 을 jsdom 이 안 푼다. 재려 들면 **되돌려도 통과하는 시험**이 된다.
층을 나눈다:

| 층 | 무엇을 보나 |
|---|---|
| 단위 시험 | 저장 키 · 허용 배율 · 로그인 사용자가 바뀔 때 복원 |
| 정적 검사 | 대상 화면에 **새 raw `font-size: Npx`** 가 들어오지 않는지 (allowlist 방식) |
| 실제 브라우저 | 보통↔크게 전환 뒤 대표 글씨의 `getComputedStyle().fontSize` 가 **커지는지** |
| 레이아웃 | 주요 화면에서 `scrollWidth > clientWidth` · `scrollHeight > clientHeight` 탐지 |
| 눈 | PC·모바일 스크린샷 비교, 마지막은 **실제 iPhone**에서 입력 포커스·지도 핀치 |

## 고정 높이는 미리 고치지 않는다

864곳을 선제 수정하지 않는다. **1.25 에서 실제로 넘치는 것만** 고친다.
위 '레이아웃' 검사가 그걸 찾는 역할이다.
