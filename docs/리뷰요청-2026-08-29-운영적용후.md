## 2. 로그인 기록 — 자동 로그인도 남긴다 (적용 완료)

**문제**: `auth_record_auto_login` 이 `last_login_at` 만 갱신하고 `login_logs` 에
안 넣어서, 자동 로그인만 하는 사람은 기록이 옛 날짜에 멈춰 보였다
(45명 접속 · 기록 4건. 어떤 분은 8월 10일).

**고친 방법**: 같은 함수에서 **오늘(Asia/Seoul) 기록이 없을 때만** insert.

```sql
begin
  if not exists (select 1 from login_logs
    where user_id = p_user_id
      and (logged_in_at at time zone 'Asia/Seoul')::date
          = (now() at time zone 'Asia/Seoul')::date) then
    insert into login_logs (user_id) values (p_user_id);
  end if;
exception when others then null;   -- 기록 실패가 로그인을 막으면 안 된다
end;
```

확인은 롤백 안에서 했다: 두 번 불러도 하나만 남고, 오늘 기록이 없으면 남긴다.
`revoke` 하지 않았다 — anon 이 불러야 하는 기존 함수다 (권한 유지 확인함).

**묻고 싶은 것**
4. `exception when others then null` 이 과한가? 로그인 경로라 안전을 택했는데,
   조용히 실패하면 "기록이 왜 안 쌓이지" 를 다시 못 찾게 되는 것도 사실이다.
   어디에 흔적을 남기는 게 좋을까?
5. `not exists` + `insert` 사이의 경쟁. 같은 사람이 두 기기에서 동시에 열면
   두 줄이 들어갈 수 있다. 하루 두 줄은 큰 문제가 아니라 그냥 뒀는데,
   유니크 인덱스(user_id, 날짜)로 막는 편이 나은가?
6. 이 표가 커지는 속도(하루 최대 62행)를 감당할 정리 정책이 필요한가?
