# 새 회중 세우기

> 2026-08-23 작성. 아직 **한 번도 해 보지 않았다** — 처음 할 때 걸린 것을 여기 적을 것.

## 먼저 알아야 할 것

**코드는 복사하지 않는다.** 저장소 하나에 Vercel 배포를 여러 개 붙인다.
그래야 버그를 고칠 때 `git push` 한 번으로 모든 회중이 고쳐진다.
회중마다 다른 것은 **환경변수(어느 Supabase 를 보느냐)** 뿐이다.

**DB 는 회중마다 따로 만든다.** 한 DB 를 나눠 쓰면(멀티테넌트) 쿼리 하나에
조건을 빠뜨리는 순간 남의 회중 명단·주소·방문 기록이 보인다. 그리고 그건
아무도 알려 주지 않는다. 비용(3곳부터 월 $25)을 내더라도 갈라 두는 편이 낫다.

**'프로토타입 DB' 를 따로 만들어 두지 않는다.** 우리 DB 에 새 SQL 을 돌릴 때마다
프로토타입에도 돌리는 일을 사람이 계속 기억해야 하고, 그건 반드시 실패한다.
대신 필요할 때 **우리 DB 에서 구조를 뽑고**, `npm run verify-install` 로
**살아 있는 우리 것과 대조**한다.

## 비용

무료 활성 프로젝트는 계정당 2개다. 그 다음부터 유료.

| 회중 | 구성 | 월 |
|---|---|---|
| 1~2곳 | 무료 2개 | $0 |
| 3곳 | 무료 2 + Pro 1 | $25 |
| 4곳 | 무료 2 + Pro 2 | $35 |
| 5곳 | 무료 2 + Pro 3 | $45 |

무료 프로젝트는 일주일 안 쓰면 멈춘다 (다시 열면 깨어난다).

## 순서

### ① Supabase 프로젝트 만들기
지역은 가까운 곳(Northeast Asia / Southeast Asia). 만들 때 정한 **DB 비밀번호를
적어 둔다** — 나중에 구조를 넣을 때 필요하다.

### ② 확장 켜기
Dashboard → Database → Extensions 에서:

```
pgcrypto    비밀번호 해시 (로그인)
pg_cron     매일 정리·봉사 알림·세션 자동 종료
pg_net      푸시 발송 (Edge Function 호출)
```

### ③ 구조 넣기
**그때그때 우리 DB 에서 뽑는다.** 미리 뽑아 둔 파일은 낡는다.

```bash
# pg_dump 필요 (brew install libpq)
/opt/homebrew/opt/libpq/bin/pg_dump "<우리 DB URL>" \
  --schema-only --schema=public --no-owner --no-privileges \
  -f /tmp/schema.sql
```

`/tmp/schema.sql` 을 새 프로젝트 SQL Editor 에 붙여 넣어 실행한다.

> ⚠ `--schema=public` 은 **public 스키마만** 담는다. cron 작업(cron 스키마)과
> 스토리지 정책(storage 스키마)은 따라오지 않는다 — ④에서 따로 넣는다.

### ④ cron 작업 등록
`supabase/applied/` 에서 `cron.schedule` 이 들어간 SQL 을 찾아 그 부분만
새 프로젝트에서 실행한다.

```
v3_data_retention.sql          매일 정리 (KST 04:00)
v3_daily_service_digest.sql    오늘의 봉사 알림
v1plus_auto_service_session_v2.sql  세션 자동 종료
v2_service_logs_developer_only.sql
v3_management_tools.sql
```

### ⑤ 스토리지 — **건너뛴다**
비공식 봉사를 사진에서 지도 핀으로 옮기면서 스토리지를 안 쓴다
(`docs/비공식-봉사-재설계.md`). 사진 기능을 쓰기로 하면 그때 버킷과 정책을
만든다.

### ⑥ Edge Function 배포

```bash
supabase link --project-ref <새 프로젝트 ref>
supabase functions deploy send-push
supabase functions deploy cleanup-chat-images
```

### ⑦ 푸시 열쇠(VAPID) 만들기
**회중마다 새로 만든다.** 우리 것을 복사하면 그 회중 앱에서 우리 회중 사람들에게
알림을 보낼 수 있게 된다.

```bash
npx web-push generate-vapid-keys
```

- 공개키 → 그 회중 Vercel 환경변수 `VITE_VAPID_PUBLIC_KEY`
- 비밀키 → 그 회중 Supabase `app_private_settings` (Edge Function 이 읽는다)

### ⑧ Vercel 배포 만들기
**같은 저장소**를 보는 새 프로젝트를 만들고 환경변수만 그 회중 것으로 넣는다.

```
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
VITE_NAVER_MAP_CLIENT_ID     주소마다 등록이 필요하다 (약관·한도 확인)
VITE_VAPID_PUBLIC_KEY
```

⚠ **우리 회중의 Vercel 주소는 절대 바꾸지 않는다.** 바꾸면 홈화면 PWA·로그인
세션·푸시 구독이 전부 무효가 된다 (CLAUDE.md 참고).

### ⑨ 검사

```bash
npm run verify-install -- --target-url https://xxx.supabase.co --target-key <service_role>
```

표와 함수가 우리와 같은지 대조한다. 빠진 것이 있으면 ③을 다시 한다.

### ⑩ 첫 관리자 계정
아직 화면이 없다. SQL Editor 에서 직접 넣는다 (트리거가 PIN 을 해시로 바꾼다).

```sql
insert into public.app_users (login_id, name, pin, role)
values ('admin', '관리자 이름', '0000', 'admin');
```

첫 로그인 뒤 **바로 비밀번호를 바꾸게 한다.**

### ⑪ 그 회중이 채울 것
관리자가 로그인해서 자기 것부터 만든다. 우리 데이터는 하나도 넘어가지 않는다.

```
설정 → 지역 관리        지역(구·시) 추가
구역 → 새 구역 카드      지역·동·번호
사용자 관리             집단 이름, 계정
```

### ⑫ 사람들 설치
홈화면에 PWA 추가 + 알림 허용. 이때 푸시 구독이 만들어진다.

## 처음 할 때 확인할 것

이 문서는 **해 보기 전에 쓴 것**이다. 실제로 세워 보면 여기 없는 것이 나온다.
나오는 대로 이 문서에 적어야 두 번째 회중이 쉬워진다.

특히 의심스러운 곳:

- ③ 구조 SQL 이 한 번에 들어가는가 (함수 사이 순서, 확장 의존)
- ④ cron 작업이 무료 플랜에서 도는가
- ⑦ 푸시가 실제로 오는가 (제일 손이 많이 가는 부분)
