# anon 쓰기 차단 — 운영 적용 절차

리뷰 판정: **조건부 GO** (비밀번호 전달 방식 수정 + PWA 갱신 공지). 둘 다 반영했다.

## 왜 공지가 필요한가

전환 뒤에는 **세션 토큰 헤더를 보내지 않는 앱은 쓰기가 전부 실패한다.**
읽기는 그대로 된다. 그래서 증상이 "앱이 안 열린다" 가 아니라
**"저장이 안 된다"** 로 나타난다 — 사용자는 권한 문제나 서버 장애로 생각한다.

⚠ 그리고 이 앱은 **새 서비스워커가 준비돼도 열린 페이지를 자동으로 새로고침하지 않는다**
(`src/lib/pwa.ts` 의 `onNeedRefresh` 는 알림만 하고 적용은 사용자가 버튼으로 한다).
그러니 "알아서 갱신되겠지" 는 성립하지 않는다.

## 공지 문안 (적용 전날 또는 몇 시간 전)

> **[안내] 필드맵 점검 — 앱을 한 번 껐다 켜 주세요**
>
> ○월 ○일 ○시경 잠깐 점검이 있습니다.
>
> **점검 전에 앱을 한 번 껐다가 다시 열어 주세요.** 그러면 끝입니다.
> (앱을 지우실 필요는 없습니다. 껐다 켜기만 하면 알아서 최신으로 바뀝니다)
>
> 혹시 설정 화면에 "지금 업데이트" 버튼이 보이면 그걸 눌러 주셔도 됩니다.
>
> 안 하시면 점검 뒤에 기록이 저장되지 않을 수 있습니다.
> 그럴 때도 앱을 껐다 켜면 바로 정상으로 돌아옵니다.

⚠ 문구 규칙 둘 (실제로 겪은 것):
- **"최근 앱 목록에서 지운 뒤" 를 쓰지 말 것.** 앱을 삭제하라는 말로 읽힌다.
- **시키는 것은 하나만.** 62명 중 어른이 많다. 방법을 둘 늘어놓으면 아무것도 안 한다.

2026-09-05 이후에는 업데이트 안내의 **지금 업데이트** 버튼으로 적용한다.
작성 중 강제 새로고침을 막기 위해 20초 자동 적용은 제거했다.
옛 버전에서 최초 전환하거나 안내가 안 뜨는 경우에는 앱을 완전히 종료 후 실행한다.

## 순서 (리뷰 권고 반영)

```
1. 새 앱 배포 (이미 되어 있음 — lib/supabase.ts 의 헤더 fetch)
2. 공지: "점검 전 PWA 완전 종료 후 재실행"
3. 짧은 점검 시간 시작 (쓰기 뜸한 시간대)
4. npm run backup                      ← ⚠ **적용 직전에.** 기다리는 사이 자료가 바뀐다
5. 운영에서 _PREFLIGHT_전환SQL_정책이름_대조.sql  → **0행** 확인
6. npm run apply:lockdown -- --confirm qdxemvdorasoryfysuoq
7. 운영에서 _VERIFY_전환결과.sql        → 검증 통과 문구
8. 실제 앱에서 손으로:
     · 관리자로 쓰기 1건 (예: 공지 하나 올렸다 지우기)
     · 일반 사용자로 자기 정보 수정 1건
9. 오류 지켜보다가 점검 종료 공지
```

## 비밀번호 (⚠ 방식이 바뀌었다)

명령줄에 넣지 않는다 — `~/.zsh_history` 에 남고 `ps` 로 다른 프로세스에서도 보인다.
`.env.local` (gitignore 됨) 에 한 줄:

```
SUPABASE_DB_URL=postgresql://postgres.qdxemvdorasoryfysuoq:<비밀번호>@...pooler.supabase.com:5432/postgres
```

Supabase Dashboard → 초록 **Connect** 버튼 → **Session pooler** (포트 **5432**).
`6543`(Transaction pooler)은 쓰지 않는다. 직접연결(`db.<ref>.supabase.co`)은
**IPv6 전용**이라 안 닿는다.

스크립트는 비밀번호만 떼어 `PGPASSWORD` 로 넘긴다 — argv 에 안 남는다.

## 되돌리기

`--single-transaction` 이라 **실패하면 자동으로 전부 롤백**된다.
적용에 성공한 뒤 되돌려야 하면 `supabase/tools/_REVERT_...sql` 이 있지만,
⚠ 그건 **anon 쓰기를 다시 통째로 여는 것**이다. 진짜 급할 때만.

## 이건 완료가 아니라 1차 봉쇄다

`TEMP_session_gate_*` 는 **'로그인했나' 만** 본다. 이번 목적은
"인터넷의 아무나 쓰기" 를 즉시 닫는 것이고 그건 달성한다.
그러나 **승인된 계정 하나가 탈취되면 대부분의 표를 여전히 고치고 지울 수 있다.**

→ 역할별 권한으로 좁히는 것은 별도 작업. **다른 회중 배포 조건 = TEMP 정책 0개.**
   기존 회중에도 담당자와 기한을 정해 둘 것.
