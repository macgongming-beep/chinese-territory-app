### 2. `not in ('admin')` NULL 함정 — SQL 준비됨, 운영 미적용

`v_role not in ('admin','developer')` 은 `v_role` 이 NULL 이면 **참이 아니라 NULL** 이라
`raise` 를 안 탄다. 즉 **없는 토큰이 그대로 통과한다.**

12개를 전부 확인했다:
- ✅ 7개는 null 처리가 있다 (`create_notice_tx` · `import_building_tx` ·
  `merge_duplicate_buildings_tx` · `rename/purge_user_name_references` ·
  `update_calendar_event_tx` · `update_calendar_event_series_tx`)
- ✅ `delete_informal_asset_secure` 는 `verify_session()` 을 먼저 불러 던지므로 안전
- ⚠ **고쳐야 할 둘**: `update_daily_service_settings` ·
  `update_global_push_quiet_settings` — **다행히 지금 anon 에 회수돼 있다.**
  `if v_role is null or v_role not in (...)` 로 고치고 grant 를 되돌린다.
  → 그래야 `알림 설정`의 전역 항목이 다시 동작한다.
- 낮음: `get_daily_service_settings` · `get_global_push_quiet_settings` 는
  읽기 전용이라 급하지 않다 (설정값은 비밀이 아니다).

## 이 저장소의 규칙 (어기면 조용히 샌다)

- **`security definer` 함수를 만들면 `revoke`.** PostgreSQL 은 만들 때 PUBLIC 에 준다.
  새로 만들 때마다 `supabase/tools/_AUDIT_anon이_부를수있는_definer.sql` 을 돌린다
- **시험을 쓴 뒤 코드를 일부러 망가뜨려 그 시험만 실패하는지 본다.**
  오늘만 헛도는 시험을 여섯 개 잡았다. 통과하는 시험과 무는 시험은 다르다
- **조립을 보는 시험이 없으면 배선이 끊긴 것을 못 잡는다.**
  편집기 단위 시험은 `initial.visitor` 를 직접 넣어 통과했는데, 정작 화면이 그 값을
  안 넘기고 있었다 — 열었다 저장만 해도 남의 기록이 되는 상태였다
- **화면에만 있는 권한은 권한이 아니다.** 표를 직접 쓰는 경로가 있으면 서버에서 막는다
- **`security definer` 안의 `current_user` 로 HTTP와 cron을 구분하지 않는다.** 항상
  함수 소유자로 보인다. cron과 UI가 공유하면 비공개 core + 검증하는 wrapper로 나눈다
- **SQL Editor 는 `begin/commit` 을 안 지킨다.** 위험한 마이그레이션은
  `npm run apply:lockdown` (psql `--single-transaction`)
- 비밀번호를 명령줄에 쓰지 않는다 (`.env.local` 의 `SUPABASE_DB_URL`)
